1.
clone
‘git clone <repo-url>’ copies the remote GitHub repository to my local computer.
It provides the complete project and its Git history, so I can develop locally.

create branch
‘git switch -c <branch-name>’ creates a new branch and switches to it.
A branch is a separate line of work, so my changes won’t affect ‘main’ until I merge them.

create index.js (Create index.js)
I created a new file named ‘index.js’ in my working directory.
At this point, Git treats it as an untracked file.

add
‘git add .’ moves the file into the staging area.
This tells Git that I want to include this file in my next commit.

commit
‘git commit -m “...”’ saves the staged changes as a snapshot in the local repository.
The commit message is used to describe what changes were made.

push
`git push -u origin <branch-name>` uploads my local branch and commits to GitHub.
Afterward, others can view this branch, and I can initiate a pull request.
2.
Pull the latest changes before editing.
Run git pull before making changes, so I am not working on an old version of the files.

Use a branch and review changes before committing.
Do not edit and commit directly on main. Create a branch, check by git status and git branch.
3.
Forgetting to create or switch to a new branch.
If I edit files on main, my changes may mix with the main.

Forgetting to git add before git commit.
If I forget add, the commit may miss files.
