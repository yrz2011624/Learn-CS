# Learning a Difficult Concept: Git Working Areas

## Concept
I am learning Git working areas: working directory, staging area, and local repository. I also want to understand `git add` vs. `git commit`.

## Part 1 — Analogy
Git is like packing a lunchbox.

- Working directory = kitchen counter: I edit files here.
- Staging area = lunchbox: `git add` chooses what goes into the next commit.
- Local repository = fridge with labeled lunchboxes: `git commit` saves a snapshot.

This helps me see that editing a file is not the same as committing it. `git add` is choosing; `git commit` is saving.

## Part 2 — Focused and Diffuse Mode
**Focused Mode:** In a small test repo, practice `git status`, `git diff`, `git add`, `git commit`, and `git log`. Draw the flow: Working Directory → Staging Area → Repository.

**Diffuse Mode:** After practice, take a walk or do something else. Later, draw the three areas from memory and explain the lunchbox analogy without notes.

## Part 3 — Learn Over Time
First, I practiced once: edit a file, `git add`, `git commit`. Then I took a break. Later, I rebuilt the process without looking at notes.

- Difficult at first: I thought `git add` saved changes permanently.
- Clearer after returning: staging is only preparation for the next commit.
- Still need practice: `git diff --staged`, unstaging, and `git add -p`.
